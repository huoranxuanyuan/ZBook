# 代码结构与任务流程

ZBook 使用 Tk 桌面界面，正文识别、图片下载与格式转换在后台执行。以下描述当前实现，不表示所有模块已经完全解耦。

## 模块边界

| 模块 | 主要职责 |
| --- | --- |
| `app.py` | 界面控制器、任务状态、结果事件分发、预览与关闭流程 |
| `ui_layout.py`、`ui_widgets.py` | 窗口布局、按钮及原生文件拖放桥 |
| `smooth_tree.py`、`layout_widgets.py` | 像素滚动列表、目录和滚动控件 |
| `core.py`、`outline.py` | 书籍元数据、章节识别、自动分卷与目录节点 |
| `input_sources.py`、`batch_limits.py` | 多格式文本读取及导入预算 |
| `covers.py`、`cover_sources.py` | 来源检索、图片下载、候选匹配和缓存 |
| `cover_browser.py`、`safe_network.py` | 独立浏览器补搜、网络请求边界 |
| `cover_design.py`、`safe_image.py` | 文字封面与图片解码入口 |
| `preparation.py` | 批量封面任务，不重新识别目录 |
| `epub_export.py`、`batch.py` | EPUB 生成、MOBI 编码、输出发布与任务报告 |
| `preview_cache.py`、`cache_maintenance.py` | 会话预览缓存、活动资源保护和清理 |
| `settings_dialog.py`、`reading_style.py` | 设置事务和共享排版默认值 |
| `paths.py`、`branding.py` | 数据路径、名称、版本与作者信息 |
| `tools/check.py`、`tools/release.py` | 独立测试入口与发布组包校验 |

## 从导入到转换

1. 导入路径交给 `batch_limits` 扫描，先检查数量与大小，再创建 `BookJob`。
2. 后台解析输入、识别目录并保存会话预览；主线程接收事件更新列表和当前书。
3. 点击列表时读取已整理的预览；仅显式“重新识别”重新处理目录。
4. 独立封面任务处理全列表，保留已有图片，通过事件应用结果并汇总未匹配项。
5. 转换使用书籍状态的副本，重新读取输入，按偏好补封面，生成 EPUB，再调用编码器生成 MOBI。
6. 输出先写入暂存文件，再以不覆盖同名目标的方式发布；校验成功后处理任务中间缓存。

## 线程与事件

Tk 控件只由主线程操作。工作线程把带任务标识的事件写入队列，`ZBook.pump()` 按时间片处理。目录结果使用版本号过滤过期任务，防止移除书籍或取消之后的结果重新占用界面。

Windows 原生拖放回调仅读取有上限的路径并入队；后续 Tk 轮询调用正常导入流程。不要在原生消息回调里直接调用 Tk 或 `after()`。

关闭会停止或等待活动任务，释放解析线程池并完成缓存收尾；已生成的电子书和原始输入保留。维护清理使用活动资源标记，避免清理仍在使用的浏览器配置或预览。

## 当前维护重点

主控制器仍集中管理多个功能。进一步拆分应围绕导入、目录、封面与转换任务逐步进行，并保持事件和取消语义；不宜将大范围重构与功能修复混在同一提交。本轮公开源码整理统一代码格式、文档和开发脚本，应用逻辑结构保持一致。
